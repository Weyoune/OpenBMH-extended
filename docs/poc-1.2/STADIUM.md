# Original stadium management

The typed career opens the existing A–H overview, stadium investments, periphery
and stadium-data screen for the active German or English club manager. Native
and typed sessions share the complete stadium request handler and projection.
Prices, construction periods, optional acceleration, sponsor participation,
payment refusal and season-ticket compensation remain the existing Core calls.

Each window owns a scope and sequence, the current manager/club identity, mode
and revision. Block edits retain the immutable Core quote. Investment tiers and
periphery offers retain their actual selected prices and current construction
state. Retired windows, changed quotes and legacy unscoped requests cannot act
through the typed owner. A close is itself an acknowledged stadium operation.

Source uses the saved random checkpoint for discounts, quote variation and
block/investment headings. Desktop workspaces now materialize that existing
`transfer_market.checkpoint_game_seed`; they do not substitute the numeric
reference's initial scratch value. Watcom still owns acceleration offers,
shortening and relevant sponsor/payment effects. Both accepted seeds, account
counters, current/future stand values, facilities, flags and construction periods
publish together. No date is advanced by these desktop actions.

Construction and compensation notices use the explicit numeric reference,
actual crest and restored stadium underlay. Publication waits for the visible
request and presenter to complete. A stopped presenter restores the draft,
world, financial changes, scope/sequence and random streams; retrying cannot
charge the first partial attempt again. The normal SDL entry supplies both
Original notice presenters.

World schema **29** adds the optional per-manager `stadium_curve_flags` byte.
It retains the Original six curve switches and absolute/relative selection.
The lower price-scenario selector uses its existing saved numeric field. Older
unknown curve preferences remain unknown through projection; the data screen
does not invent them. The construction-discount input is already owned by the
manager's match/staff state and is not duplicated in the new schema.

The existing 144,000-place extension remains: standard maxima are
14k/24k/14k/20k/14k/24k/14k/20k. Larger stands retain size-aware periods of at
least two weeks per maximum thousand places, with the edition's prices. These
are deliberate existing extensions, not claims about the Original limits.

Typed club records do not yet contain stadium-name offsets. The stadium footer
uses Source's club-name fallback; it never borrows another club's stadium name
from the reference installation. Renderers, nested confirmations and periphery
text wrapping accept the supplied reference and avoid reopening a legacy EXE.

Synthetic checks cover shared requests, Core discount/periphery operations,
sponsor-notice rollback and window generations, plus saved curve compatibility.
Private GUI checks exercise all A–H rows, capacity input, actual stand and
facility construction, periphery, curves, save/reload, funds refusal and positive
compensation. Stopped financial presenters and retries are compared with the
complete independent Core world and RNG result. Screenshots and matching FBMs
remain private; these checks are not complete played seasons or a Beta release.
