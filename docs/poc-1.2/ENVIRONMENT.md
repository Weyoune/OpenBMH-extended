# Typed environment budgets

The Original environment screen now opens for the typed active club manager.
Youth teams, the co-trainer, doctor and physio retain their existing six monthly
budget controls. The verified Core environment rules are installed from the
numeric reference. The screen uses that explicit reference and the actual crest
resource; dual-world data is not admitted through the legacy executable loader.

Requests carry the current manager/club, revision, opening owner and a monotone
window request identifier. Each opening receives a distinct identifier range,
so even an unchanged request from a closed window cannot be replayed after
reopening at the same gameplay revision. Root ownership and the pending visible
request are both checked before applying the Core `set_environment` operation.

Changed budgets publish the existing career/environment state under one new
revision. An unchanged level is acknowledged without a new gameplay revision.
The edits do not charge cash immediately, draw either random stream or advance
the date; the existing subsequent monthly services own billing. Invalid/stale
requests preserve the accepted state. Closing releases the modal owner.

No new saved budget representation is introduced: the six monthly values and
youth status already belong to ManagerCareerState. Window ownership is transient.
Private single-English and mixed-country Original GUI tests exercise every level
control, compare the stored budgets with Core, save/reload, acknowledge an
unchanged click and reject retired-window input. Screenshots and matching FBMs
remain private. Native build checks and complete career/release gates are tracked
separately; this menu does not finish the live/calendar or annual integration.
