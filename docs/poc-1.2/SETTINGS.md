# Settings and original EIN files

Extended owns the Original 20×9 presentation matrix as optional
`economy.presentation_options` in world schema 31. Fresh careers copy the actual
reference defaults once. Every byte, including availability and non-Boolean
values, survives world/FBM roundtrips. Older careers retain an unknown matrix;
they cannot open this menu or start the integrated match receipt by borrowing
current reference preferences.

The Original menu-19 screen, font, grid, mouse edit directions, source limits,
linked availability and right-click exit are reused with an explicit numeric
reference. `settings_request_source.hpp` supplies the same checked byte edits to
both career implementations. Manager, revision, expected 180 bytes and window
sequence are authenticated. Leaving and reopening retires the previous owner.
Headless callers without sound capabilities cannot change audio-driver cells;
the SDL entry supplies actual playback availability and applies the saved music
and click switches.

Saved preferences are installed in Core projections before desktop/match work.
They therefore drive drawer handles, drag raster, shortcut visibility,
background/text formatting and the existing match presentation consumers.
Integrated matches use the saved matrix rather than an all-one placeholder.
No settings operation advances the date, spends money or draws random numbers.

## EIN files

The original load/save controls use exactly 180 raw bytes, without FBM headers or
new encodings. Targets are regular files within the configured save directory;
overwrite requires confirmation. Saving constructs the complete replacement
view and stages the career before writing an exclusive temporary. Readback,
flush and atomic publication precede the live session/view swap. Failure keeps
the prior file and live career. Cancelling the chooser returns to its settings
window, retaining the window owner.

Import preserves original raw values and recomputes only Source availability,
retaining the raw audio-driver flags. File length is checked before reading.

## Indoor tournament calendar

Q5 is connected to admission of German indoor appointments. Its actual saved
byte is tested as in the Original: zero permits German `0x4002`, any nonzero
value suppresses it. The English `0x4002` remains League Cup and is unaffected,
including when the active manager is English in a mixed game. The original
source calendar is retained intact; only the current day ticket is filtered.
A suppressed indoor-only date is quiet, while an English cup or another league
on the same date still requires its real competition owner and results.

The Original mode availability and inclusive season-day 110–230 refusal remain.
Projection supplies the saved season and calendar origin to Core, so later
seasons use their current season day. The native SDL refusal uses the Original
timed manager notice, returning to the settings screen without an edit, clock
advance or random draw. Interrupted presenters preserve the career; callbacks
cannot resurrect a settings owner retired while the notice was visible.

EIN imports also honor this refusal when changing Q5; they cannot bypass event
ownership. See the intentional Extended-only import decision in
[compatibility](../COMPATIBILITY.md). Unknown saved indoor policy is explicit
when admitting a German indoor date, without borrowing a current template.

This connects the switch and disabled-date progression. Simulation and visible
ownership of an enabled indoor tournament remain a separate completion gate.

## Desktop time limit

H8 now uses the existing Original process clock. Only its minute setting is saved;
the monotonic timestamp and remaining time are process-owned. The context uses
session scope, canonical manager seat, date and event identity, so normal staged
Session copies and revisions cannot reset a manager's time. A new manager/event
receives a fresh budget. A successful career load restarts runtime time, whereas
a failed load retains the existing paused remainder.

The Original top-row percentage raster is reused. Settings, EIN/readme and game
save/load waits pause time; changing H8 applies only the final minute difference
when the wait ends. Zero disables it and re-enabling from zero starts fresh.
Other Original blank numeric values retain their existing inactive gate and
nonzero delta semantics. MEN retains its existing key-input owner without
pausing the clock. Normal management menus continue consuming time.

Expiry uses `StartupFlow::process_timer_expired`, including the existing modal,
calculator and mouse-release waits. It first unwinds supported management
screens, then emits the Original desk event8 for the actual current manager.
Existing Core turn validation remains in charge. An unfinished day/presenter
boundary preserves the career and does not re-dispatch every frame at the same
revision. Opening a new owned state permits a fresh validated attempt.

This does not wire missing match/season presenters or make the development
entry a completed playable Beta. Neither monotonic time nor runtime expiry
receipts are serialized, and sampling consumes no gameplay random numbers.

## Separate owner still required

R5 (secondary-league admission) remains unavailable. EIN imports changing it are
explicitly refused. Other cells retain the native consumer whitelist and
Original availability, rather than accepting every displayed coordinate.

The in-settings readme uses the explicit reference and the existing original
file-availability behavior. General live-match settings ownership and complete
season/release qualification remain separate work.

## Verification

Public synthetic checks cover shared write/replay guards, sound capabilities,
numeric bounds and odd speeds, schema 31 raw bytes, explicit unknown schema 30,
confined EIN paths and failed-publication preservation. Private Original-input
GUI checks cover single English and mixed English/German actors, source-grid
edits, dependent locks, desktop consumers, save/load/confirmed overwrite,
malformed and unowned-cell EIN rejection, chooser cancellation, retired windows
and unchanged full gameplay/RNG state. Platform/runtime results are recorded
with the private screenshots and matching saves; a build alone is not GUI QA.

Additional checks compare admitted German/English appointments to the Original
calendar kernel for all representative raw values, retain source calendars,
reject stale policy tickets, preserve real cup stops, and resume a quiet
indoor-only date. Private boundary captures use a clearly identified controlled
calendar with actual clubs/assets and no invented played scores, at season-two
days 109/110/230/231; they are not multi-season playthrough evidence.

Desktop-clock checks use controlled monotonic timestamps to cover cloned/staged
sessions, canonical handoffs, settings and file waits, H8/EIN, raw disabled gates,
failed load/cancel preservation, ordinary-menu expiry and one refused transition
per revision. Actual SDL wall-clock observations are recorded separately from
these deterministic simulations in the private QA evidence.
