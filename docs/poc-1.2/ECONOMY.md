# Economic state, daily interest and weekly settlement

World schema **16** added an optional career economy. The current writer uses schema17 (planned stand targets/flags and the submitted
plan); schema1–16 source packs and
older development snapshots remain readable; no missing account fields are
silently inferred when running an economic phase. S9 remains the outer typed save
container. Fresh GUI careers explicitly initialize economic state before desktop
entry from the supplied initial reference. A reference mailbox must be empty;
an unrelated played career cannot supply defaults.

The new state retains verified numeric fields: deposits, interest-income and
overdraft-interest totals, all five bank/human-loan contracts per manager,
construction countdowns, remaining weekly offer bytes, camp countdown/quote/visit
flags, and the 52-sample weekly financial/facility histories. History words retain
the Source 32-bit representation, including signed balances. Existing account,
sponsor, stadium and tactical fields remain in their existing typed records.
The two offer bytes already represented by match state are not stored twice.

Loan columns are bank, then the four **global manager seats**. Bounded workspaces
use a checked complete seat permutation for both borrower records and lender
columns. Fund/share holdings, mailbox recipients and read flags use that same
mapping, including sparse active seats. Inactive-seat data remains intact; a
missing active raw account is not replaced by a fabricated zero account.

`daily_finance` requires an explicit `DailyEconomyKind`. `after_event` runs the
account/deposit/overdraft calculation without moving stocks. `plain_day` first
runs the shared stock routine. This reflects the different Source callers and
prevents moving prices twice after an event. The normal legacy daily routine
still visits its four original raw records; typed processing visits the actual
active managers and preserves both random streams.

`settle_weekly_managers` reuses the extracted Core manager settlement: debt offer,
camp countdown and bill, insurance payments, contract/bonus bookkeeping and weekly
statistics. This is the existing Core calculation and contract-request behavior;
it does not supply the still-missing weekly manager-offer/negotiation UI. The
native full weekly function calls the same extracted step in its old position.
The phase commits accounts, full tactical/season data and the extra economic
fields together, rejecting external state changes.

The persistent mailbox stores up to forty entries with exact 150-byte Source
text, date, recipients and read flags, plus the unread-recipient latch. Shared
insertion/eviction code preserves the current Classic behavior. New pending
transfers and weekly injury/recovery notices are retained in this mailbox and
survive snapshots. Earlier setup messages generated by full native season setup
are a separate presentation/import concern: financial-template comparison clears
that already-produced queue explicitly rather than claiming it was imported.
Mailbox navigation/display and earlier setup-message delivery remain open.

Validation covers hand-calculated daily interest and overdraft tiers, deposits,
sparse loan/holding/mail mappings, camp settlement, rolling histories, mailbox
capacity, snapshot/schema compatibility and interrupted-owner rollback. Eight
actual-data comparisons match complete Core financial state, full boards,
stock/holding blocks, both RNGs and snapshots. Twenty-four frozen-predecessor and
current Core stock/interest/weekly/training runs produce byteidentical save
streams and RNG traces. These are controlled Core regressions, not fresh DOS
recordings or complete played-career tests.

The application still needs the complete daily owner: weekly manager incidents
and choices, market countdown/bids/settlement, monthly services and a general
calendar/event cursor must be integrated in the correct order. These economic
phases do not advance time or enable a playable 1.2 release on their own.
