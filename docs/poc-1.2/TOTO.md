# Owned Toto coupons and settlement

The typed desktop opens the Original Toto screen, including team ratings,
crosses, the stake calculator, its timed Present phases and the previous result.
The saved appointment supplies its existing global fixture selection; no scores
or replacement fixtures are generated by the UI. Fewer than eleven selected
matches retains the Original unavailable screen.

Native and typed submissions share the existing Core coupon operation. A
submission stores the stake and eleven picks without charging the account,
advancing the date or drawing randomness. Manager/club, revision, visible pending
request and a per-opening identifier range must match. Retired-window input and
replayed submissions are rejected. The renderer and stake dialog use the
explicit numeric reference, without loading the data package as a legacy EXE.

World schema **30** adds optional `economy.pools`: four canonical manager coupons,
the shared previous outcomes and the season/day owning pending stakes. Coupons
retain stake, winnings, tips, hit count and Source's void marker separately.
Projection remaps manager seats, never club/player identities into coupon bytes.
Older unknown records stay unknown; the new menu does not invent historical bets.

Selected league and domestic-cup fixtures are observed by the actual Core Toto
evaluator. The resulting receipts carry canonical fixtures and 1/0/2 outcomes.
In particular, cup extra time or shootouts must not replace the outcome that
Source evaluated earlier. Observation does not generate results or consume RNG.

The prepared event owner settles the shared coupon after all real calculations,
before publishing its complete staged result. It reuses `settle_pools_coupon`:
charge the stake, count hits, pay the Original 10/20/50 times stake for nine, ten
or eleven hits, then clear the stake. Insufficient funds posts the Original
message and retains the preceding winnings/hit record. Receipts must be complete
and unique; pending stakes must belong to that season/day. Notifications use the
played event's date, even after the calendar transaction moved to its next day.
Cleared stakes cannot be charged again after a reload or repeated settlement.

Synthetic tests cover Original limits, shared submissions, sparse manager seats,
quotas, insufficient funds, duplicate receipts, repeated settlement and codec
compatibility. Private GUI tests submit eleven home picks through the Original
calculator, save/reopen, reject stale input, and play the same real league date
with and without the stake. Scores and RNG must match; only the expected Toto
account/result fields differ. Screenshots and matching snapshots remain private.

This packet completes this owner for the already supported prepared league and
domestic-cup programmes. It does not complete normal visible match/clock
presenters, remaining competitions, annual transitions or the Beta release gates.
